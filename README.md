# YT Learning Platform

An AI-powered educational platform that transforms YouTube playlists into interactive learning experiences. Ask questions about any playlist and get precise answers with exact video timestamps.

## Features

- **Hybrid Search**: Combines BM25 lexical search with vector similarity for accurate retrieval
- **Automatic Citation**: Responses include direct links to specific video moments with timestamps
- **Conversation Memory**: Persistent chat history with automatic summarization; older messages are compressed into a rolling summary while the last 6 are kept in full
- **Multi-Query Retrieval**: Reformulates queries to improve document matching
- **Async Transcript Loading**: Concurrent extraction with rate limiting and proxy support
- **Multi-Agent Orchestration**: Three specialized agents (Supervisor, Analyst, Teacher) coordinated by a LangGraph graph. The Supervisor routes each request; specialist agents handle research or content generation
- **Quiz and Exam Generation**: The Teacher agent creates multiple-choice quizzes (JSON) and formatted PDF exams from playlist content
- **Web Search Fallback**: When a question falls outside the indexed playlist content, the Analyst can perform a real-time web search via Tavily

## Agents

### Supervisor

Lightweight coordination agent. Reads the full conversation context, the current query, and any output from a prior delegate, then decides whether to respond directly to the user or dispatch to a specialist.

- Uses `GENERATION_MODEL`. Should be the most capable model in the setup — it generates all user-facing responses and makes every delegation decision.
- No tools. Output always contains one of three markers parsed by regex: `RESPOND:`, `ANALYST:`, or `TEACHER:`
- Can chain agents across a single user request: e.g., Analyst -> Supervisor -> Teacher -> Supervisor -> user

### Analyst

ReAct agent for information retrieval and research. Searches and processes playlist content from the vector store, reconstructs transcripts, summarizes large texts, and falls back to the web when needed.

| Tool | Description |
|---|---|
| `chunks_from_query` | Semantic search in Chroma with scope filtering (`playlist_id`, optional `video_ids`). Uses BM25 + semantic ensemble + MultiQueryRetriever. |
| `chunks_from_scope` | Raw chunk retrieval by scope, bypassing semantic ranking. Used when full coverage matters more than relevance. |
| `chunks_to_transcript` | Sorts chunks by `start_seconds` and joins them into a readable transcript. Must receive chunks from a single video. |
| `search_on_web` | Tavily web search (top-1 result). Used when needed information is absent from the vector store or requires up-to-date external data. |
| `summarizer` | Offloads summarization to a separate LLM call to avoid filling the agent's context window. Accepts optional instructions (length, focus, format). |

### Teacher

ReAct agent for generating educational evaluation material. Always receives content prepared by the Analyst, never fetches data itself.

| Tool | Description |
|---|---|
| `create_quiz` | Validates a JSON quiz structure (exactly 4 options A–D per question) and returns the confirmed JSON. |
| `create_exam` | Receives a complete HTML string generated by the agent, renders it to PDF via WeasyPrint, saves to `output/exams/<filename>.pdf`, and returns the path. |

## How It Works

### Content Ingestion

This happens once per playlist at startup.

1. Provide a YouTube playlist URL. `YouTubePlaylistLoader` extracts playlist and video metadata via the YouTube Data API v3.
2. Transcripts are loaded asynchronously via `YoutubeLoaderWithProxy`, with a configurable delay between requests and optional Webshare proxy credentials to avoid rate limiting.
3. Each transcript is chunked into 30-second segments with 100-character overlap. Each chunk carries metadata: `video_id`, `video_title`, `playlist_id`, `start_seconds`, `end_seconds`.
4. Chunks are embedded and stored in Chroma, scoped by `playlist_id`. Multiple playlists can coexist in the same vector store. Subsequent runs detect the playlist is already indexed and skip ingestion.

### Request Lifecycle

This runs for every user message.

1. The user submits a question. `MemoryManager` loads the session context: a rolling summary of older messages + the last 6 messages verbatim.
2. The graph starts at `agent_manager`. The Supervisor receives context, the current query, and any prior `agent_output`, then emits a marker.
3. `RESPOND:` - the Supervisor replies directly to the user; the graph exits to `END`.
4. `ANALYST:` - the graph routes to `agent_analyst`. The Analyst runs a ReAct loop over its tools and returns a result to `agent_output`. Control returns to `agent_manager`.
5. `TEACHER:` - the graph routes to `agent_teacher`. The Teacher generates quiz JSON or exam HTML, calls `create_quiz` or `create_exam`, and returns the result to `agent_output`. Control returns to `agent_manager`.
6. Steps 3-5 can chain: a single request like "create a quiz on topic X" follows the path Supervisor -> Analyst -> Supervisor -> Teacher -> Supervisor -> user.
7. After `RESPOND:`, `MemoryManager` persists graph state via `AsyncSqliteSaver` and updates the rolling summary if the message count exceeds `MAX_MSG_SUMMARY` (default: 6).

## Setup

### Prerequisites

- Python 3.11+
- YouTube Data API key
- Tavily API key (for web search)
- API key for your chosen LLM provider (Anthropic, OpenAI, etc.)
- API key for your chosen embedding provider (VoyageAI, OpenAI, etc.)

### Installation

```bash
# Clone the repository
git clone https://github.com/Iamzhitox/yt-learning-assistant.git
cd yt-learning-assistant

# Create virtual environment
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Configure environment
cp .env.example .env
# Edit .env with your API keys
```

### Environment Variables

```env
# REQUIRED
GOOGLE_API_KEY=           # YouTube Data API v3
TAVILY_API_KEY=           # Tavily web search
DEFAULT_CHAT_ID=          # UUID of the chat session to load/resume

# LLM — provider-agnostic via LangChain init_chat_model
LLM_PROVIDER=anthropic    # or openai, google-genai, etc.
QUERY_MODEL=claude-haiku-4-5        # used by Analyst, Teacher, and Summarizer
GENERATION_MODEL=claude-sonnet-4-5  # used by the Supervisor — should be the most capable model

# Embeddings — provider-agnostic
EMBEDDING_PROVIDER=voyage
EMBEDDING_MODEL=voyage-3.5

# API keys (only set the ones you need based on your provider choices)
# ANTHROPIC_API_KEY=
# OPENAI_API_KEY=
# VOYAGE_API_KEY=

# OPTIONAL
PROXY_USER=      # Webshare proxy username
PROXY_PASS=      # Webshare proxy password

# PERSIST_DIR=./db     # Chroma vector store path (default: ./db)
# LANG=en              # Transcript language preference

# Retrieval tuning
# SEARCH_TYPE=similarity
# SEARCH_K=2
# ENABLE_HYBRID_SEARCH=true
# MMR_DIVERSITY_LAMBDA=0.7
# MMR_FETCH_K=20

# Debug
# DISPLAY_OBSERVATIONS=false   # Print agent tool calls and node transitions to stdout
```

## Usage

```bash
python main.py
```

The application will prompt you to enter a YouTube playlist URL, then you can ask questions about the content.

## Tech Stack

- **Orchestration**: LangGraph, LangChain
- **Vector Store**: Chroma
- **LLM**: Provider-agnostic (Anthropic, OpenAI, Google, etc.)
- **Embeddings**: Provider-agnostic (VoyageAI, OpenAI, HuggingFace, etc.)
- **Persistence**: SQLite, SQLModel
- **Web Search**: Tavily
- **PDF Generation**: WeasyPrint
